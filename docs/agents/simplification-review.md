# 简化审查补充规则

状态：已采用。作为现有 code-review 的 Standards 补充，用于本次差异中的删除、合并、状态收敛或依赖替换；Spec 轴继续独立核对 issue、规格和验收范围。普通业务切片只检查相关差异，有明确的模块调查任务时才沿调用关系扩大范围。

## 五项证据要求

1. **消费证据。** 用 rg 定位符号、配置、事件和调用，区分生产、测试、文档与示例。检查动态工具注册、graph 路由、HTTP/MCP 入口、启动路径和外部格式；静态未引用不足以证明可删除。
2. **净维护收益。** 说明实际减少的接口、状态、配置、实现、专用测试和文档，以及迁移后仍需维护的部分。依赖替换优先检查内建与已有依赖，再权衡新增包的语义覆盖、版本和部署成本；移动代码或增加转发层本身不构成收益，不设删行配额。
3. **受保护行为。** 对照当前规格和相关 ADR，说明审核、恢复、原始资产、空间验证、结果未知和环境分离是否变化。类型检查不能替代模型 JSON、HTTP/MCP、文件、数据库或跨进程结果的边界校验；范围变化先更新规格。
4. **真实路径验证。** 通过实际消费入口验证保留行为。既有测试可依据规格修正，但删除实现专用测试时需说明剩余行为覆盖；GIS 预期来自独立依据，Mock、返回 success 或观测无异常不替代真实产物验收。检查范围遵循[测试规范](../testing.md)。
5. **可实施结论。** 给出少量可证明的结论，说明证据、取舍、最小改动、验收与任务归属。与已有票据重叠时沿用该票据；调查默认报告候选，代码修改、任务发布与远端操作遵守当前用户授权。

## 本项目的判断边界

[ADR-0001](../adr/0001-persistence-and-observability.md)拥有 Checkpoint、业务执行记录和 LangSmith 的职责。共享 task ID 不代表它们重复；简化现有 ExecutionTrace 前必须迁移其必要业务事实及消费点。[ADR-0002](../adr/0002-reviewed-local-workflows.md)和[V1 规格](../specs/0001-qgis-workflow-agent-v1.md)拥有审核、单执行、QGIS 进程分离和未知写入结果等约束。

多种结构是否冗余，以事实的权威来源、更新责任和真实消费为依据。保留承担独立职责的表示与验证；已确认的运行约束不能仅因代码更短而取消。

## 审查输入与输出

主 agent 向 Standards 审查者提供固定比较基线或明确工作区差异、仓库规范及本页；向 Spec 审查者提供同一差异、相关 issue/spec 和 AC。两轴分别报告，不能用规范通过替代需求通过。

每个候选至少交代：

- **结论：** 保留、合并/删除、证据不足。
- **证据：** 文件/符号、生产消费链或检索范围，以及当前行为的权威来源。
- **收益与取舍：** 实际减少和仍需维护的内容，最强保留理由与可能失去的能力。
- **验收与归属：** 最小可实施切片、必要检查、已知风险和对应任务；范围变化交给规格决定。

“证据不足”不能作为已证明死代码的删除建议；“保留”可用于解释容易被误删的职责。仅报告与差异或调查任务有关的内容；没有可证明的问题时直接报告无发现，不为满足数量制造候选，也不默认全库扫描。业务切片与远端操作继续遵循[开发规范](../development.md)和[tracker 规则](issue-tracker.md)。
