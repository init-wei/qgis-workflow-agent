# 自主开发交接

用户已确认 V1 方案，本轮只完成 T00 和开发前置配置。后续 agent 可在收到开发任务后直接从本页开始，无需重新访谈。当前业务验收尚未通过，不能根据环境成功关闭后续任务。

## 入口与任务前沿

1. 进入本仓库，确认工作分支为 `codex/v1-refactor`，读取 AGENTS、CONTEXT、V1 spec、相关 ADR 和[环境报告](../onboarding/baseline-2026-10-30.md)。本分支是本轮集成基线，master 保留原型。
2. 执行 `uv run --locked python scripts/issue_frontier.py`，实时查询 GitHub 原生依赖与领取状态。T00 关闭后首个可领取任务是 [T01 #21](https://github.com/init-wei/qgis-workflow-agent/issues/21)。按 T 编号优先选择；T04 不能阻塞核心 GIS 开发。
3. 读取所选 issue 完整正文和评论。声明领取、当前运行 ID、分支及具体文件范围。多个 agent 不同时修改同一文件、协议或锁文件；T02/T03 逻辑独立但共享运行文件时顺序处理。
4. 一张票一个新上下文。先通过公开接口取得失败证据，再做最小实现与回归；不要一次重写整个仓库。已知原型问题及类型错误在 T01 中处理。
5. 逐条验收；运行适用检查；Standards 与 Spec 两个独立审查者审阅同一差异。给 Standards 附仓库规范；涉及简化改动或简化调查时再附[简化审查补充规则](simplification-review.md)。给 Spec 附当前 issue/spec 和 AC；普通切片以相关差异为范围。修复并复核后本地提交，把 commit、命令、结果和限制贴入正式 issue。
6. 验收满足后关闭当前 issue，重新查询前沿；不要依赖文档中的旧状态。需要最终集成的票据不能在未集成时提前关闭。推送、PR 和合并遵守该开发任务的人类授权。

编排可以由一个主 agent 按依赖顺序调用子代理完成，不要求长期守护进程或新的 agent 平台。主 agent 维护共享接口和组合验收；默认选择 gpt-6-luna/max，无法使用则记录实际模型。子代理独立文件范围；不能把对方“完成”的文字当成测试证据。

## 固定约束与完成条件

- 唯一应用库 PostgreSQL；Checkpoint、业务执行记录和 LangSmith 各司其职，具体见 ADR-0001。
- T01–T03 先得到可信真实闭环。T04 实际 LangSmith 平台凭据缺失时只阻塞该项观测验收；T05/T06/T07 继续。默认关闭观测。
- 业务测试采用真实 GIS 的独立数值/几何判定，先小样例和费用试跑，再做正式对照实验。API key 不进浏览器、任务正文、日志、checkpoint 或提交。
- 任一批准不能因为次数上限或超时被跳过；写入结果不明不得自动重放。原型单测断言与新 spec 冲突时修正断言，不保留错误行为以求测试通过。
- 核心完成需 AC01–AC16 对应的核心证据；观测增强独立报告。若 T04 未验收，不宣称整套规划全部完成。T08 包含干净重建、浏览器、GIS、两条组合、恢复、异常和诚实简历证据。
