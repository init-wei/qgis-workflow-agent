## 结论与推荐形式

核心方法用于 QGIS Workflow Agent；第一步已将项目规则补充到已有 code-review 的 Standards 审查，并允许在明确模块范围内作简化调查。生效规则由[简化审查补充规则](simplification-review.md)拥有，现阶段复用已有流程。

本项目已有 ask-matt 的规格→切片→实现/测试→Standards 与 Spec 审查、codebase-design 的模块判断及 GitHub tracker。DSH 方法用于为“为什么可以删除/合并”补充消费证据；代码审查仍检查当前差异，简化调查则可以沿调用关系调查指定模块，两者互补，不要求每张业务票都先全库审计。

第二步的封装方向已确认，触发条件、入口形式和当前状态均由生效规则末节拥有；本页保留来源、迁移取舍与适配分析。

## 可保留、需改写与不迁移

| 原 skill 内容 | 本项目处理建议 | 原因 |
| --- | --- | --- |
| 先 rg 搜消费点，区分生产、测试、文档与示例 | 保留 | 先证明存在冗余，避免凭大小、名字或直觉删代码 |
| 查多个地方是否镜像同一事实 | 保留并结合当前 ADR | 适合计划、SSE 和浏览器状态收敛，但不同职责的数据不能混为重复 |
| 清理空洞校验、无消费抽象与实现专用测试 | 保留证据要求，改写保护规则 | 跨模型、文件、网络、QGIS 进程和数据库的校验仍是必要契约 |
| 分析异步所有权、结束、取消和资源释放 | 保留 | 可用于 SSE、任务执行、连接池和 QGIS 连接；执行中取消承诺仍由 V1 spec 限定 |
| 有合适内建/依赖时替代自研基础设施 | 保留选择标准，改用 Python/JS 实际依赖 | 先已有库/内建，再比较新增包的残余胶水、部署和版本成本，不为少几行引入新框架 |
| 删除重复注释、保留非显然契约和取舍 | 保留 | 链接当前文档规范；不用导入 DSH 双语与文档同步体系 |
| DSH twin LLM adapters、JSONL persistence、Cordis 等受保护设计 | 不迁移具体规则 | 本项目受保护的是 PostgreSQL、审核、必要业务记录和独立 QGIS 等已确认约束 |
| packages/*、ACP、Bash 后台任务等调查分区 | 替换 | 分为计划/运行、QGIS/MCP、Web UI；只有指定范围需要广度时才并行 |
| Agent Notes 生命周期、归档成组三份文件、原 PR 整理 | 不迁移 | 本项目用 GitHub issue、Git 规格、根级 ADR；避免第二套状态与提案系统 |
| pnpm doc-sync/lint、DSH validator、pre-push 假设 | 不迁移 | 使用本项目适用命令；当前类型检查存在已记录基线，不能冒称通过 |

## 已采用的审查规则

五项证据要求及审查输入/输出已移至[生效规则](simplification-review.md)，本页不再维护另一份正文。当前只核对相关差异或明确调查范围，不将每张业务票扩展成全库简化审计。

## 适配的关键取舍

DSH 的删除建议依赖它自己的架构和实际消费证据。本项目最容易误用的地方是把不同职责的记录、跨进程验证或已确认运行约束看成重复：这也是迁移时增加项目边界判断的原因。具体职责由 [ADR-0001](../adr/0001-persistence-and-observability.md)、[ADR-0002](../adr/0002-reviewed-local-workflows.md)和规格拥有；审查执行要求只在[生效规则](simplification-review.md)维护。
