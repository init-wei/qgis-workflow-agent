# 方案模板与审核

方案定义维护在 [六类目录](../../agent/skills/README.md)，由版本化 JSON 和 `RegisteredSkill` 校验器共同约束。目录拥有模板、变量、标签、别名、输入条件和真实来源；不再从 Cookbook 代码或成功 trace 自动发布模板，也不新增模板数据库。

规划器按需求和已选文件元数据提供参考候选。共享渲染器将当前受控文件引用与模板声明的示例参数填入完整 TaskPlan 示例，保留数字、布尔值和列表类型。这些参数是例子，实际计划必须按当前需求和元数据生成。文件角色的预览顺序不代替用户需求，审核时仍应核对来源与裁剪面的对应关系。

候选进入模型上下文，不能直接进入执行器。模型生成的最终 TaskPlan 依次经过占位符检查、输入与新输出绑定、完整计划校验、Processing 参数与空间预检，再等待计划批准；需要风险审核的调用继续独立审核。没有候选时仍走同一条规划与执行路径。缺参、类型错误、未知或未解析占位符不能被文件绑定悄悄覆盖。

本轮新规划的 `TaskPlan.metadata.skill_candidates` 由服务端记录开关状态、所提供候选的 ID、版本和来源；它不证明模型实际使用、匹配正确或新任务成功。旧原型允许模型写入任意 metadata，历史计划中的同名注释不能作为人审事实。界面只展示计划记录的引用及其任务、修订，并链接目录当前版本；模板审核以版本化目录和可追溯的真实审阅记录为准，需与引用版本核对。最终结果仍以必要业务记录、真实产物和空间验证为依据，用户结果确认单独保存。

## 策划与人工审阅

目录中的策划、代理代码审查、真实任务验证与人工模板审阅分别记录。新候选先标记 `agent_curated`、`pending_human_review`，不得把来源任务的成功或代理审查改写为人类已审阅了新模板。六份初始版本的真实维护者确认见[审阅清单](skill-review.md)；模板审阅状态不拥有执行批准。

维护者确认具体模板版本后，应记录 `human_reviewed` 及审核者、带时区的时间、真实证据、对应 ID、版本和规范化内容 SHA。结构校验只证明这些字段与内容一致，不能自行证明真实人审发生过；尚未经过真实确认的条目不填写人审记录。模板变更需要重新核对来源与适用条件；源任务来自组合链时，只引用实际验证过的相应步骤。不能将一份固定样例的数量、面积或字段值当成任意新输入的预期。

六份初始模板的范围、来源、内容摘要与核对要点集中在[审阅清单](skill-review.md)。

## 开关与开发复验

`QGIS_AGENT_SKILLS_ENABLED` 默认 `true`；设置为 `false` 并重启后台可关闭候选提示，其余校验和审核保持相同。该开关用于开发和后续 A0/A1 实验，不赋予额外工具权限。正式实验的配置、留出集、重复数与指标以[评测约定](../implementation-plan.md#评测执行约定)为准，直接渲染执行不混入模板提示效果。

使用新的受控数据、距离或字段发起请求，在计划审核中查看参考候选及实际调用，批准前检查没有输出或图层变化。执行后核对新输入与产物、实际类型和参数、独立数值预期，再单独确认结果。测试命令与证据见[测试规范](../testing.md)和[正式 T06](https://github.com/init-wei/qgis-workflow-agent/issues/26)。

旧 `/trace-demo` 只保留历史静态 trace 与草稿诊断，不能作为真实执行或模板审阅证据。直接构造已批准计划的 `run_skill_reuse_smoke.py` 已退出；V1 从浏览器主页面进入同一业务流程。
