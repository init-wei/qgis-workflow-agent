# V1 浏览器演示与复验

本页使用仓库中的微型合成数据，演示真实浏览器审核、受控 QGIS 调用和结果确认。每次运行都是新的任务：模型可能要求澄清或生成不符要求的计划，必须检查实际计划和结果，不能把本页的预期当作本次运行通过的证据。正式验收及当前版本的实测证据见 [AC 证据入口](acceptance.md)和 [T08 issue](https://github.com/init-wei/qgis-workflow-agent/issues/28)。

## 准备

按[环境入口](README.md)安装锁定依赖、准备专用 QGIS profile、启动项目 PostgreSQL、QGIS、MCP 和后台，并用 `./scripts/dev.sh build` 构建前端。浏览器使用 `http://127.0.0.1:9000/`；这是后台提供的生产构建入口，不需要启动 Vite。`/settings` 可直接打开并刷新。确认只使用本项目专用数据库、工程和 profile，端口被占用时先确认归属，不接管其他服务。模型凭据只在服务端配置；LangSmith 默认关闭，另见[观测配置](langsmith.md)。

固定输入及预期由[合成样例说明](../../tests/fixtures/gis/README.md)拥有。加载演示直接使用跟踪的 `tests/fixtures/gis/phase11_points.geojson`。其他演示使用系统 GDAL 生成独立 T06 开发样例；在仓库根目录运行：

```sh
/usr/bin/python3 scripts/build_t06_fixtures.py --output-dir /tmp/qwa-t06-demo-inputs
```

输出目录必须不存在；如已存在，改用另一个不存在的目录，不覆盖或删除旧输入。生成的 `t06_places.geojson`、`t06_regions.gpkg` 和 `t06_window.gpkg` 的定义、当次文件 SHA 与生成器 SHA 由输出清单记录。GeoPackage 字节随生成时间可能变化，以当次清单为准。可用 `sha256sum` 对原输入和上传前后的文件复核，记录页面显示的受控 `file_id`、SHA 和选中图层。输出另存于任务独立位置，切勿覆盖输入。

侧栏“点击或拖拽上传文件”会上传并选中输入；每项可用复选框选择或取消。只勾选当前请求需要的文件；多图层 GeoPackage 还须明确选定图层。查看页面给出的来源、CRS、几何、要素数与字段，再提交请求。若计划的文件 ID、具体调用、参数或输出与请求不符，填写意见并选择“拒绝并重新规划”；不要批准偏离要求的计划。每次拒绝或明确修改后，核对同一 `task_id` 的新 revision 和完整调用。模板候选仅是参考，不能代替对当前计划的批准。

## 一次真实加载

1. 新建会话，上传并只选择 `tests/fixtures/gis/phase11_points.geojson`。核对页面显示 `EPSG:4326`、Point、3 个要素和 `id/group/value` 字段，记录输入 SHA 及批准前 QGIS 图层数。
2. 发送固定请求：

   > 加载已选择的 phase11_points.geojson 图层，显示名为 T08 当前真实加载。只做这一次加载，不截图、不保存工程。

3. 在“审核 TaskPlan”中核对所选文件 ID、显示名和恰好一次 `add_layer`；不应出现额外截图、工程保存或新空间文件。批准前记录图层数、业务 attempt 和输出目录状态。实际 MCP 发送次数须由独立传输或服务端记录核对，不能只把业务 attempt 当作传输计数；[当前浏览器专项定义](../../tests/fixtures/gis/t08_browser_routes.json)要求批准前 0 次、结束后累计 1 次。
4. 选择“批准执行”，在 QGIS 实际读回新增图层的来源、EPSG:4326、3 个点、属性和坐标，对照[固定预期](../../tests/fixtures/gis/t08_browser_routes.json)。检查同一 task/revision 的业务记录 `GET /api/executions/{task_id}`，以及原输入和上传副本的 SHA 未变；加载来源引用不算新生成文件。
5. 在结果确认前核对工具完成、空间验证与用户确认是不同事实，此时 `confirmed` 应为 null。只有实际结果符合要求才选择“任务成功”，继续至最终状态，再检查没有新增调用或修改输入。不能取得独立 MCP 计数时，将该项记为 unknown 或 not_run。

完成后刷新并重选同一会话，核对“业务执行记录”卡的 task/r、已批准参数、尝试或审核记录、实际返回、验证与确认；历史对话摘要仅供参考。T08 初次请求的多词名称曾被缩成 `T08`，当次未批准；复现时如遇此情况，明确拒绝意见：“显示名必须完整等于引号内的‘T08 当前真实加载’，包括空格和中文；保持所选文件与仅一次加载”。核对同任务新修订后再决定是否批准。原始失败与纠正过程均见[重建实测](clean-rebuild-2026-10-31.md)。

## 新文件与组合任务

以下均为开发样例，不是 T07 留出集，也不保证每次模型规划均成功。每个请求新建任务；在审核中检查有向前序产物的实际引用，不用显示名或模型叙述代替文件绑定。输出 GPKG 必须新建且可读，实际 CRS、字段、几何、数值及 SHA 应与[独立预期](../../tests/fixtures/gis/README.md)核对后才确认。

| 场景与选中输入 | 可以提交的明确请求 | 审核和读回重点 |
| --- | --- | --- |
| 重投影 → 缓冲 → 查看：`t06_places.geojson` | 将选中的点先重投影到 EPSG:32650，保留属性并输出新的 GeoPackage；再逐点做 250 米、每象限 8 段、不融合的缓冲，保留属性并输出新的 GeoPackage；只加载最终缓冲图层。 | 第二步消费已验证的第一步实际输出；缓冲单位为米，`SEGMENTS=8`、`DISSOLVE=false`。结果为 4 个点缓冲，逐个对照正 32 边形半径、面积、周长和原属性。 |
| 裁剪 → 按字段融合 → 查看：`t06_regions.gpkg` 的 `regions`、`t06_window.gpkg` 的 `window` | 用 window 裁剪 regions，保留属性；将裁剪结果按 `zone` 融合，不拆分不相连部分，分别输出新的 GeoPackage，只加载最终融合结果。 | 两个输入角色正确，融合使用实际裁剪产物；四个裁剪面积为 6、8、4、2 m²，E/W 融合并集面积分别 10/6 m²，非分组属性来自各组实际成员。 |
| 裁剪 → 全部融合 → 面积统计：同上 | 用 window 裁剪 regions，将结果全部融合且不拆分不相连部分，计算投影平面面积并统计该面积的总数、和、最小值、最大值；各处理结果输出新的 GeoPackage，不加载图层。 | 四步均引用前序实际产物；EPSG:32650 的面积单位是 m²。裁剪后并集面积为 16 m²，融合后为一个要素；不要将单面面积和 20 m² 当作并集面积。 |
| 数值与分类统计：`t06_regions.gpkg` 的 `regions` | 分别对原始 regions 的 `amount` 做基础统计和按 `zone` 分类统计，报告总要素数、非空数、空值数、和、最小值、最大值，输出两个新的 GeoPackage 表，不加载图层。 | 两个统计均消费同一个原始输入：总 4、非空 3、NULL 1、sum 19、min 3、max 9；E 总 2/非空 1/sum 7，W 总 2/非空 2/sum 12。基础表数值字段的 `count` 是非空数，不能直接称总要素数；分类表 `count` 也按非空值理解，总数与 NULL 数由经过核验的原输入等事实确定。 |

如需 T05 另一组合及空结果反例，在不存在的新目录执行 `/usr/bin/python3 scripts/build_t05_fixtures.py --output-dir /tmp/qwa-t05-demo-inputs`，再按[裁剪、融合与统计复验](../testing.md)选用 source、clip mask 或 far mask。合法空结果、工具失败、产物验证失败和未知结果分别记录；不要以一张地图截图或工具返回成功代替空间读回。

## 审核恢复与受控工程副本

在新的会话中选择固定三点输入，请求先加载该图层，再另存受控目录中的**新** `.qgz` 工程副本，保留原输入和原工程，保存须独立风险审核。核对计划只包含请求的调用、文件和新工程目标；不要将计划批准当成保存工程的风险批准。

分别在计划审核、风险审核、结果确认三个等待点，按[恢复复验](../testing.md)刷新、重选会话、选择“稍后处理”并切换会话，再从专用后台正常退出和重启，保留 PostgreSQL、MCP、QGIS。核对同一 task、revision、审核身份及参数；已完成前缀、图层数和产物 SHA 不能因恢复增加或变化。计划可拒绝并填写修改意见，旧修订不能授权新修订。风险批准前不得出现新工程文件；批准后独立打开副本并检查图层来源和内容，原工程不应改变。结果确认前 `confirmed` 仍为 null。

同一时刻只有一个 GIS 任务可执行；忙时不排队。停止读取只关闭事件订阅，不能视为取消 QGIS 操作。外部写入结果不明时先核查实际工程、图层、文件及原进程，记录所见；旧调用不自动重放，已核查也不等于成功。确需继续时新建任务并重新审核。

## 当次记录与排错

为每次演示保存 commit、实际依赖/QGIS 版本、请求、文件 ID 与输入 SHA、计划和 revision、批准/拒绝、独立 MCP 调用计数、业务 attempt、产物路径和 SHA、空间读回、确认及重启前后状态。浏览器页面错误和必要静态资源也单列。日志和产物留在忽略目录，分享前仅导出脱敏的最小证据；不要提交密钥或真实数据。复现步骤和每种验证的边界以[测试规范](../testing.md)为准。

缺失 CRS、单位、字段或输出角色时补充明确要求；计划错误时拒绝并记录新修订。若模型多次规划失败、服务不可用或验证未通过，保留实际失败与现场，不以离线测试或旧结果替代本次演示。GeoPackage 出现 `-wal`、`-shm` 或 `-journal` 时停止并先由操作者处理事务；不要仅凭主文件 SHA 宣称内容稳定。当前版本浏览器路线与退役静态演示接口应按[专门定义](../../tests/fixtures/gis/t08_browser_routes.json)分别检查，不改写历史 T07 七项浏览器结果。
