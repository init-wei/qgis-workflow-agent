# SPEC-QWA-V1：可审核、可恢复的本地 GIS 工作流 Agent

状态：最终规划基线；未实现。日期：2026-10-30。已确认选型见[已确认决策](../adr/README.md)。

## Problem Statement

现有原型已经具备结构化规划、MCP、QGIS 与审核界面，但源码存在自动批准、附件未传入、拒绝后未恢复、协议试错、双计划模型与结果证据不足等问题。用户难以确信“批准的计划、执行的操作、交付的结果”一致；开发者也缺少能用于简历与回归的真实评测依据。

## Solution

将原型收敛为一个可在本机重建、操作范围明确的 GIS 工作流 Agent。用户选择或上传小型矢量数据，以自然语言提出受支持任务，审阅具体参数后执行；系统验证空间产物、展示结果并允许确认或反馈。应用持久化自己的流程和业务结果，开发者通过可选 LangSmith Cloud 观察调用并分析实验。

## User Stories

1. 作为本地用户，我希望上传或选择输入数据，以便任务使用明确的数据文件。
2. 作为本地用户，我希望看到输入的图层类型、CRS 和字段，以便发现错误数据或歧义。
3. 作为本地用户，我希望知道当前支持哪些 GIS 任务，以便提出系统可完成的请求。
4. 作为本地用户，我希望在执行前查看步骤、输入输出、算法和关键参数，以便作出有依据的批准。
5. 作为本地用户，我希望拒绝并填写修改意见后，在同一个任务中获得新计划，以便完成迭代。
6. 作为本地用户，我希望高风险操作另行明确审核，以便普通计划批准不等于授权所有后续行为。
7. 作为本地用户，我希望进行重投影和缓冲等组合，以便后一步明确使用前一步的产物。
8. 作为本地用户，我希望得到可读取的空间文件和统计结果，以便继续在 QGIS 中使用。
9. 作为本地用户，我希望结果说明区分工具完成、空间验证和人工确认，以便不会把技术返回当作任务成功。
10. 作为本地用户，我希望文件、参数或单位不足时收到明确问题，以便补齐信息后再执行。
11. 作为本地用户，我希望刷新或重启后恢复审核等待点，以便不会丢失尚未作出的决定。
12. 作为本地用户，我希望切换会话时不会误批另一任务，以便审核内容与任务身份一致。
13. 作为本地用户，我希望运行错误或结果未知时能理解原因和产物状态，以便决定下一步。
14. 作为本地用户，我希望复用已验证方案处理新文件和新参数，以便减少重复规划。
15. 作为开发者，我希望关闭云端观测后仍可运行和查询结果，以便平台不是业务依赖。
16. 作为开发者，我希望将一次失败关联到模型、工具和验证过程，以便有效排错。
17. 作为项目维护者，我希望在固定任务集上比较版本，以便用可复现结果判断模板和检索是否有价值。
18. 作为求职者，我希望项目描述与提交、产物和原始评测相符，以便能够解释个人贡献及能力限制。

## 首期功能范围

### 输入与单机运行

- 单用户、本地回环访问；一个应用后台进程与独立 QGIS 测试 profile/工程。
- GeoJSON、GeoPackage 中明确指定的一个 2D 矢量图层；多图层容器由用户指定图层。上传产生受控文件引用，不将浏览器路径当成服务器路径。
- 大型影像和完整空间文件不进入模型上下文。原始输入保持不可覆盖；每次任务有独立输出位置。
- 多个会话可以处于审核等待点，同一时间只有一个执行中 GIS 任务。忙时提示，不排队，不承诺多用户并发。

### 六类任务及正确性依据

| 任务       | 支持内容                                   | 预先约定的验证依据                                  |
| ---------- | ------------------------------------------ | --------------------------------------------------- |
| 图层加载   | 加载受控输入，查询元数据并可查看           | 实际图层有效，来源、CRS、类型和预期要素数量匹配     |
| 矢量重投影 | 指定目标 CRS，生成新文件                   | 目标 CRS、要素属性/数量及已知点坐标容差             |
| 缓冲区     | 明确距离、单位与必要选项                   | 合适投影、几何有效、已知距离/面积容差；不将度当作米 |
| 裁剪       | 指定输入与裁剪面                           | 已知交集、范围、数量或面积；空结果与失败区分        |
| 融合       | 全部或按明确字段融合                       | 分组数量、属性约定与几何/面积关系                   |
| 简单统计   | 计数、数值字段的和/最小/最大、投影面积统计 | 合成数据的独立预期、字段类型与单位                  |

算法 ID、provider 和参数以本机 QGIS 实际能力为准；不承诺一份硬编码参数表适配所有 QGIS 版本。组合任务限两到四个清楚步骤，使用明确产物引用。

### 审核、恢复、结果与观测

- 计划必须完整展示将实际执行的调用。每次有效修订重新等待批准，旧批准不能授权新修订。
- 高风险辅助操作限白名单内、受控目录中的新工程保存；另行审核。任意代码、删除原始资产及覆盖原始输入不属于首期能力。
- 支持三个暂停点：计划审核、风险审核、结果确认。刷新和后端重启后恢复正确等待点。
- 执行中写操作超时或进程崩溃后结果不明，明确标为结果未知/需要核查，不自动重放。
- LangSmith Cloud 在真实闭环通过后作为可选工具接入；模型、图调用和自定义执行/验证通过业务 ID 关联。业务无需从云端 trace 读取批准或结果。

### 方案模板与知识依据

- 沿用并精简已有 Skill 模型，人工审阅六类基础模板，保留真实验证来源。
- 模板选择先用任务标签、别名、输入条件与现有轻量匹配；候选进入规划或渲染为待审阅草稿，保持数值/布尔等参数类型。
- 当前算法能力、输入元数据和必要版本事实进入规划。完整文档检索、语义向量索引与知识图谱按后续错误分析再决定，不是 V1 交付条件。

## Implementation Decisions

- 保留 Vue、FastAPI、LangGraph、MCP、PostgreSQL 和独立 QGIS 的基本组合。
- 计划 Module 只有一种权威 TaskPlan；类型化调用与步骤、输入输出引用一并验证。移除运行时旧 Plan 兼容链和隐式 fallback 执行。
- 运行 Module 统一新任务和恢复任务的事件输出；审核状态和位置以 checkpoint 为准，浏览器阶段由后端快照投影。
- 已有 ExecutionTrace 精简为必要业务执行事实，保存输入引用、参数、尝试结果、产物与校验结论。类名不是契约，不维持两套并行记录模型。
- PostgreSQL 承担 checkpoint 与应用业务数据；LangSmith 保存观测分析副本。平台停用不改变业务成功判定。
- GIS Adapter 统一配套插件和 wrapper 的协议；单次写操作结果未知时不切换协议并重复调用。
- 输入与参数在 Interface 处集中校验；内部已验证类型不层层兜底。模型初始计划自动生成最多两次，仍失败则明确返回；用户修订不会触发自动批准。
- 使用少量显式业务表和直接持久化操作，不引入通用 ORM/Repository 框架、任务队列或事件总线。
- 密钥由项目专用环境配置读取；QGIS 继续使用发行版 Python，Agent 使用独立 uv 环境。升级单独验证。

## Acceptance Criteria

| 编号 | 可核查标准                                                                                       | 必须提供的证据                                                   |
| ---- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| AC01 | 干净 checkout 可按文档安装、构建、启动项目专用 PostgreSQL 与后台；不会操作其他项目数据库/profile | commit、锁文件、实际版本、命令与结果；原基线失败/跳过单列        |
| AC02 | 上传/选择文件确实进入计划及执行，原始文件在成功或失败后均未覆盖                                  | 浏览器路径、输入引用、执行参数及前后校验和                       |
| AC03 | 非法或不完整的计划整体不能执行；合法计划的所有必要步骤按预期顺序执行                             | 重复/缺失步骤、无效引用、缺参数、未知工具的反例及 MCP 调用计数   |
| AC04 | 未批准、拒绝及过期计划批准均不会执行；填写修改意见后同任务产生新修订                             | 公开接口与浏览器证据；拒绝多次和达到自动尝试上限的测试           |
| AC05 | 高风险操作只有匹配当前调用的明确批准才能执行；重复提交不重复执行                                 | 批准/拒绝/过期/双击场景，真实调用计数与受控新工程样例            |
| AC06 | 六类任务各有真实 QGIS 样例并通过表中的空间验证；不只检查 return success                          | 实际输入、产物、独立预期、容差、验证结果与 QGIS 版本             |
| AC07 | 至少一条重投影→缓冲→查看链，以及一条裁剪/融合/统计链实际消费前一步输出                           | 前后步骤输入输出引用和实际文件；模型改写路径不能替代引用         |
| AC08 | 三个审核暂停点均可刷新、重选会话及后端重启恢复；继续后不重复已完成操作                           | 暂停前后快照、重启记录、工具调用计数                             |
| AC09 | 切会话清除旧审核 UI，提交决策绑定正确任务与修订；执行忙时明确拒绝第二项执行                      | 两会话专项、忙时请求与浏览器表现                                 |
| AC10 | 工具完成、产物通过、用户确认分别记录；验证失败、空合法结果、结果未知均准确表达                   | 注入失败和空结果，原始工具结果与页面结论一致；假成功为零         |
| AC11 | 无 LangSmith 配置或主动关闭后，任务、审核恢复和产物查询正常                                      | 关闭观测的真实闭环与恢复证据                                     |
| AC12 | 六类模板有审阅与真实验证来源，能替换文件及参数且保留类型；命中仍须审核                           | 新文件/新参数样例、数值/布尔检查、来源和未授权调用零次           |
| AC13 | 开启 LangSmith 后能关联一次成功与一次失败/结果未知到业务记录，能解释节点、调用和验证             | 平台实际 run/trace 与 task ID；usage 缺失显示未知，不填零        |
| AC14 | 固定留出集、异常集和版本对照可复现，失败不静默剔除                                               | 原始逐次记录、汇总、配置、样本数和失败分析                       |
| AC15 | 审核/会话 UI 正确，文本不会作为任意 HTML 执行，构建后单地址和深链接可用                          | 浏览器场景及静态资源加载；类型检查与构建结果                     |
| AC16 | 最终交付真实范围、简历描述与测量一致，适用检查及两轴审查完成                                     | 演示步骤、可读取产物、测试/集成/限制记录、Standards 与 Spec 结论 |

AC10 的“假成功为零”只针对固定验收集合，不声称覆盖所有 GIS 输入。LangSmith Cloud 实际不可验证时 AC13 保持独立未验收，不阻塞核心 GIS 验证；不能用 mock 把它标成真实接入成功，也不能在其未验收时宣称整套规划全部完成。

## Testing Decisions

主测试 Seam 是应用提供的提交、查询、审核、确认和恢复 Interface。通过这些操作验证真实用户结果，而不是固定内部函数调用顺序。浏览器验证前端到后台的完整交互；GIS Adapter 可注入确定性 fake 做反例，但真实 QGIS 和真实云端分别验收。

重点测试 Module 为计划验证、运行状态与审核、GIS 参数/产物校验、模板渲染和会话 UI。确定性规则优先代码评价；语言说明可抽样人工评价，不以模型看截图代替空间判断。

现有[审核测试](https://github.com/init-wei/qgis-workflow-agent/blob/9602db0dd517ab6f0ce0ea4514174425b9a55142/tests/test_backend_review.py)、[受控执行测试](https://github.com/init-wei/qgis-workflow-agent/blob/9602db0dd517ab6f0ce0ea4514174425b9a55142/tests/test_controlled_executor_node.py)和[真实 MCP smoke](https://github.com/init-wei/qgis-workflow-agent/blob/9602db0dd517ab6f0ce0ea4514174425b9a55142/tests/test_controlled_executor_real_mcp_smoke.py)可作为测试组织参考；其中默认强制执行等旧预期必须按本规格更正。默认 CI 不要求付费模型、桌面或云端 key；真实验收单列，不把跳过记为通过。

每个行为切片先获得目标行为的失败证据，再最小实现并验证；只为有意义的行为风险增加测试。只读分析和文档整理不运行目标项目代码。

## Out of Scope

- SQLite、双数据库运行路线、通用多供应商观测 Adapter，以及自建 LangSmith/Langfuse 平台。
- 大型遥感栅格、SAM3、训练、GPU、任意 Python 代码执行、任意 GIS 算法和无界多步自动代理。
- 多用户权限、分布式 worker、消息队列、高并发、运行中 QGIS 操作可靠取消和外部副作用 exactly-once。
- 自动学习/自动发布 Skill、完整跨文档知识问答、图谱、向量数据库、默认在线模型裁判。
- 自建通用 Trace 搜索器、标注系统、评测 Dashboard；平台记录也不作为业务权威。
- 本轮的克隆、安装、实现、远端 issue/PR 发布、push、SDK 接入和真实付费请求。
