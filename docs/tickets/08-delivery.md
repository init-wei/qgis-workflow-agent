# T08：干净重建、演示与简历证据

**正式 issue：** [#28](https://github.com/init-wei/qgis-workflow-agent/issues/28)；状态以 GitHub 为准。

**What to build：** 另一位开发者按文档从干净 checkout 启动并复现演示，用户获得与实际成果一致的简历描述。

**Blocked by：** T07。观测增强另需 T04 的实际平台验收，不阻塞核心 GIS 交付。

**输入：** 规格 AC01、AC15、AC16，以及所有已完成切片的证据。

**验收：**

- [ ] 干净 checkout 可重建专用环境；构建后后台单地址、根页面与深链接正常。
- [ ] 六类任务、两条组合、审核恢复、观测开关及异常路径证据齐全；未验收外部条件明确列出。
- [ ] 适用单元/契约、数据库、前端类型/构建、浏览器和真实集成检查分别报告。
- [ ] 旧计划/事件/记录兼容链和默认静态伪演示依赖已收敛；敏感与大文件未纳入提交。
- [ ] 重新测量实际代码规模，解释超出估算的业务原因，不为减少行数删除必要校验或测试。
- [ ] Standards 与 Spec 两轴审查均核对实际差异；简历只采用个人实际贡献及实测数字。
- [ ] 原始/第三方来源与发布许可边界已核对；不凭原型占位 metadata 推断许可或署名。
- [ ] 文档包含运行、复现、产物、限制与排错；GitHub 状态/链接更新，远端 push 仍遵守明确授权要求。

**证据：** 从零重建记录、演示、全部验收矩阵、原始评测、实际规模和审查结果。本切片不以“构建通过”替代完整用户路径验收。核心和观测增强分别报告；任一明确要求的增强尚未验收时，不宣称整套规划全部完成。
