# T01：上传文件，审核计划后真实加载

**正式 issue：** [#21](https://github.com/init-wei/qgis-workflow-agent/issues/21)；状态以 GitHub 为准。

**What to build：** 用户上传一个矢量输入，看到将执行的计划、批准后在真实 QGIS 中加载，获得可查询业务结果和最终确认入口。

**Blocked by：** T00。

**输入：** 规格 AC02、AC03、AC04、AC15；现有图层加载 E2E 与审核路径。真实规划需要项目专用模型凭据，缺失时单列外部条件。

**验收：**

- [ ] 文件引用实际进入规划与执行，原始输入校验和不变；页面展示正确来源和图层信息。
- [ ] 只有一种类型化 TaskPlan，步骤、调用和引用完整校验；静默忽略调用、隐式 fallback 及强制批准已移除。
- [ ] 展示实际调用内容；未批准的计划不触发 MCP；普通拒绝带意见回到同一任务规划。
- [ ] Wrapper 与配套插件统一协议，一次工具请求不先试另一协议；加载成功在 QGIS 中可见。
- [ ] 精简业务记录可查询任务、步骤结果与产物引用；记录不依赖 LangSmith，也不新造平行 ExecutionTrace 模型。
- [ ] 首次与恢复流共用事件输出；用户文本正常显示，页面不将任意消息作为 HTML 执行。

- [ ] 原型 7 处 TypeScript 错误修复并使类型检查成为 CI 必须通过的检查；构建产物与后端静态目录统一，根路径和深链接可访问；浏览器不保存 API key。

**证据：** 浏览器→真实模型→MCP→QGIS 的加载链，非法计划的 MCP 零调用反例、业务查询结果及适用回归。旧计划适配消费点在本切片迁完删除，避免长期兼容双链。
