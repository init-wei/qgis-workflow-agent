# 规划参考模板

这里的六个 JSON 是本地版本化的 `RegisteredSkill` 定义。每项记录任务标签、别名、输入条件、变量、完整 TaskPlan 示例和原始任务证据；同一模板的调用只在该条目的 `task_plan_template` 中定义。变更模板内容时应更新版本，并核对引用的证据范围。

当前条目由 agent 根据已验证任务策划，状态均为 `pending_human_review`；历史任务的验证和 agent 的代码审查不表示新模板已由人类审阅。模板本身不批准执行，任务实例仍须经过完整计划校验、用户审核和受控执行。人类审阅事实及 T06 完成状态由正式 issue 记录。

未来发生真实人审时，条目可设为 `human_reviewed` 并填写 `human_review`：审阅人、带时区的 `reviewed_at`、证据、`skill_id`、`version` 和 `content_sha256`。内容摘要由 `skill_content_sha256(RegisteredSkill.model_validate(...))` 计算：先按模型规范化各字段，再排除 `review_status` 和 `human_review`，将其余内容以排序键、紧凑 UTF-8 JSON 编码并计算 SHA-256。版本、模板、来源及其他内容发生变化会使旧审阅不再匹配。校验只核对记录的完整性和内容绑定，不自动证明审阅事实；待审条目不能附带人审记录。模板人审状态不授权任务执行。

匹配使用请求中的标签/别名和可确认的文件条件。示例按用户选择文件的顺序绑定角色：第一项为源图层，裁剪模板的第二项为裁剪面；实际角色仍需核对。输入文件的 ID、路径和图层名来自当前选中记录，其余 CRS、距离、字段、布尔值、输出文件名是示例参数，并非当前请求或用户授权事实。缓冲示例来自“重投影后缓冲”的已验证链；是否需要重投影以及目标 CRS 均由实际需求、元数据和检查决定。

选中文件的文字元数据若包含模板语法起始符 `${`，使用该文件的候选示例会被跳过，普通规划仍可继续。示例数据自身损坏或缺少模板参数仍是错误，不会被当作未命中。

模型应根据当前请求生成唯一 TaskPlan，不能直接执行这些示例。缺少明确参数、字段、单位或可用输入时应要求修正，不能把例值当默认授权。模板开发样例与后续留出集、A0/A1 比较及验收的约定见[实施计划](../../docs/implementation-plan.md)与[测试规范](../../docs/testing.md)。
